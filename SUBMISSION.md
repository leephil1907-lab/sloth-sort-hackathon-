## TL;DR

**Don't sort your Downloads folder. Outsource it to a sloth.** My `todo list.txt` had
carried *"sort downloads folder (lol, never)"* for years, so I hired an animal with the
correct energy policy: a **397 MB open-weight model** (Qwen2.5-0.5B, Apache-2.0) served
locally by **Ollama** (MIT). It classified, renamed, and filed 24 messy files in about
a minute — on a 2-core CPU, no GPU, no internet, no subscription. Small shifts, long
naps, zero deletions. Set it and forget it.

## Slow and steady is the design spec, not a joke

Sloths survive by never spending energy they don't have to. The agent encodes that:

- **`--pace 8`** — never files more than N files per shift. 23-file disaster? Three shifts.
- **`--siesta 1`** — a little rest between files.
- **`watch --nap 6h`** — cron-free night-shift mode: file a few things at 2am, sleep 6h, repeat. It converges over days instead of minutes, which for a Downloads folder is exactly right.
- **Archive ≠ delete.** The model can *suggest* something is junk; the harness only parks it in `_archive/`. Deleting is a decision the sloth refuses to make for you.
- **Never crashes.** Bad model output → tolerant JSON recovery → extension-based fallback rule. The loop always finishes the pile.

## The stack (all open, all the way down)

| Layer | Thing | Why it's open | License |
|---|---|---|---|
| Brain | `qwen2.5:0.5b-instruct` GGUF (Q4, 397 MB) | open weights — download once, own forever, fine-tune later | [Apache-2.0](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct/blob/main/LICENSE) |
| Server | Ollama 0.40 on 127.0.0.1 (`/api/generate`) | [open-source](https://github.com/ollama/ollama/blob/main/LICENSE) model runtime & de-facto local standard | MIT |
| Harness | `sloth_sort.py` — stdlib-only agent loop (sniff → classify → move → manifest) | my code, MIT, ~450 LOC — readable in a sitting | MIT |

One-line model swap, no code changes: `--model qwen2.5:1.5b-instruct`, `llama3.2:1b`,
whatever you like. The harness talks to the local HTTP API any Ollama-compatible
server exposes.

## Why open innovation matters *here, specifically*

This isn't decorative open-source. For this exact tool, closed literally doesn't work:

1. **My Downloads folder contains a tax summary, a signed lease, and a 2019 password export.**
   A cloud classifier means uploading exactly those files to a server I don't control,
   under a privacy policy I'd have to read (laziness forbids). Local inference means
   the sensitive stuff *never leaves the machine* — that's not a settings toggle,
   it's physics. This demo folder's "sensitive" files are fake; the real one isn't.

2. **It works with the internet off, forever.**
   After the one-time 397 MB pull, this ran on a machine with no network at all —
   on a plane, in a village on bad power, during an ISP outage. Night-shift file
   hygiene should not depend on network conditions.

3. **Marginal cost is zero, and it stays zero.**
   24 files ≈ 25k input + 2k output tokens per pass. Pennies per run on even the
   cheapest hosted API — but forever, multiplied by every folder, every laptop, every
   night. Local is $0.00 at any scale, uses the idle CPU you already own, and draws
   watts, not dollars. Truly sloth-economical.

4. **The brain is swappable and tunable, not a product roadmap.**
   The 0.5B model misses ~4 of 24 placements on this mess (see honesty box). Two open
   fixes: bump to `qwen2.5:1.5b`/`3b` with one flag, or fine-tune the small one on
   *my* idea of tidy with open weights and open tooling. Closed APIs deprecate models
   and cap your customization; Apache-2.0 weights just sit on disk being mine.

5. **Auditable behavior on your own files.**
   The whole decision loop — prompt, categories, fallbacks — is 450 lines you can read,
   diff, and fork. When software is moving files named `1password-backup-2019.txt`,
   "trust us" is not an architecture.

## Where open beat closed in practice

- **Iteration speed with zero unit economics anxiety.** I re-ran the full classification
  ~6 times while tuning the prompt (demanding strict JSON, adding owner rules like
  *"leases are Documents, not Finance"*). Each pass was free. On a paid API I'd have
  been either counting tokens or, worse, shipping retries of my password export to
  someone else's logs.
- **Determinism for free.** `temperature=0` + fixed prompt + pinned local weights =
  the same plan every run. No silent model updates mid-project, no "sorry, that model
  is deprecated."
- **Hardware honesty.** The demo ran on a 2-core sandbox CPU (no GPU) at ~3 s/file.
  A closed service makes this a billing question; open makes it a laptop question.

## Honesty box: what the tiny brain got wrong

Out of 24 files, ~20 placements were right. The 0.5B model still filed the
screen-recording `.mp4` under Notes and put grandma's jollof recipe in Documents
(reason: *"recipe notes"* 🤨). Small models are like sloths: mostly right, occasionally
philosophical. The mitigations are part of the design: dry-run review, plain-English
`--instructions "recipes are Notes"` owner rules, undo, and the one-flag model upgrade.
It's a trade I choose with my eyes open — exactly what open weights let you do.

## Try it (2 minutes)

```bash
ollama pull qwen2.5:0.5b-instruct     # one-time, ~400 MB
python3 make_mess.py demo/messy_downloads
python3 sloth_sort.py scan demo/messy_downloads --pace 24
python3 sloth_sort.py apply demo/messy_downloads --pace 8 --siesta 1
python3 sloth_sort.py undo demo/messy_downloads   # changeful-of-mind insurance
python3 sloth_sort.py watch ~/Downloads --pace 8 --nap 6h   # the lazy setup (foreground)
```

### The truly lazy setup: let your OS feed the sloth

`watch` is for hobbyists. Cron is for professionals of laziness:

```cron
# crontab -e   —  02:00 every night: file 8 things, sleep 82223 seconds, repeat
0 2 * * *  cd ~/sloth-sort && python3 sloth_sort.py apply "$HOME/Downloads" --pace 8 --siesta 2 >> "$HOME/.slothsort-nightly.log" 2>&1
```

The model still runs locally, so this needs no network and no babysitting — just keep
`ollama serve` living at boot (`systemctl --user enable ollama`, launchd, whatever your
OS calls it). In a week your Downloads folder is sorted and you have, quite literally,
done nothing.
